# Design

## Context

動機は proposal.md「Why」、振る舞いは 2 つの delta spec を参照。いまの画像の大きさは `render.py` の `_picture` が `IMAGE_MAX / 長辺のドット数` で決めている。PNG の拡大率は add-slide-plugin の design.md「画像の埋め込み」と、`docs/changes.md` の「小さな格子の画像は 1024 ピクセルに届かなくてよい」の式 `min(64, max(16, ceil(1024 / n)))` で決まる。

## 合意事項（2026-10-09 設計対話、PO 回答）

- 1 ドットの寸法を固定値ではなく、目標の大きさから決め、1 ドットに上下限を設ける（式は slide-generation の delta spec「ドット絵の表示の大きさ」）。
- 値は、目標 2.4 インチ、1 ドット 0.05〜0.075 インチ。0.075 は「2.4 インチに届く絵は 32×32 以上」という PO の指定から決めた。
- 格子の 64 ドットの上限を外す。画像の長辺は 4.6 インチで頭打ちにする。
- 同梱アイコンは 16×16 のまま（表示は 1.2 インチ）。描き直すかどうかは受け入れの結果とあわせて別の変更で決める。

見本の比較に使った PPTX はセッションの一時フォルダにあり、コミットしない。

## Goals / Non-Goals

**Goals:**

- 格子のドット数だけで画像の大きさが決まり、原稿の書き手が大きさを考えなくて済む。

**Non-Goals:**

- 原稿から大きさを指定する書式。見た目は生成器が決めるという方針（slide-generation の Purpose）を保つ。
- ドット絵ツール `pixel.py` の拡大率の範囲（1〜64）。ツールの出力は利用者が拡大率を選ぶので、格子が大きくても利用者の責任で済む。

## Decisions

### 定数の置き場所

目標・1 ドットの上下限・長辺の上限の 4 つの値は `render.py` の定数として置く（いまの `IMAGE_MAX` の隣）。大きさを計算する純粋な関数を 1 つ設け、テストは関数の値とできた PPTX の画像の寸法の両方で確かめる。

### 2026-10-09 PNG の拡大率の下限を 1 にする
- Ruling: スライドに埋め込む PNG の拡大率を `min(64, max(1, ceil(1024 / n)))` にする（n は長辺のドット数）。n が 64 以下ではいまの式と同じ値になる。
- Reason: 格子の上限を外すと、いまの式では拡大率が 16 を下回らず、200 ドットで 3200 ピクセル、1000 ドットで 16000 ピクセル四方の PNG になる。長辺 1024 ピクセル以上という目的（add-slide-plugin の design.md「画像の埋め込み」）は、拡大率 `ceil(1024 / n)` で n が 1024 以下なら満たせる。
- Cost if wrong: 65 ドット以上の格子を PowerPoint が拡大したときに輪郭がにじむ。受け入れで大きな格子を貼って見れば分かる。

### 2026-10-09 説明文は画像の右端に付いて動く
- Ruling: 図のレイアウトの説明文の左端を、`MARGIN_X + IMAGE_MAX + CAPTION_GAP` の固定位置から、実際の画像の右端 + `CAPTION_GAP`（0.5 インチ）に変える。説明文の枠の幅 `CAPTION_W`（5.2 インチ）と高さは変えない。
- Reason: 画像が 0.6〜2.4 インチに縮むと、固定位置の説明文は画像から最大 4 インチ離れ、何の説明か分からなくなる。枠の幅を変えないので、`fit.py` の行数と高さの判定はそのまま使える。右端は最大でも 0.9 + 4.6 + 0.5 + 5.2 = 11.2 インチで、本文領域の右端 12.43 インチに収まる。
- Cost if wrong: 説明文の位置がスライドごとに揃わなくなる。受け入れで図のスライドを並べて見れば分かる。

### 2026-10-09 格子の大きさに上限を設けない
- Ruling: `grid.py` の `MAX_SIZE` と、幅と高さの上限の検査を消す。代わりの上限は設けない。
- Reason: PO の指定（合意事項）。原稿と格子ファイルは利用者が手元で書くもので、外から受け取る入力ではない。
- Cost if wrong: 数千ドット四方の格子では、PNG を作るメモリが数百 MB になる。そうした格子を書く利用者が現れてから、上限を戻す変更を出す。

### テストの格子

32×32、40×40、64×64、200×200、32×16 などの格子は、テストの中で文字列として作り、一時フォルダの原稿から参照する。リポジトリにファイルとして足さない。画像の寸法は EMU の丸めがあるので、期待値との差を 2 EMU まで許す。

## Risks / Trade-offs

- [同梱アイコンが 1.2 インチで小さく見える] → 受け入れで PO が見て、描き直しを別の変更で決める（合意事項）。
- [`docs/changes.md` の拡大率の式が古くなる] → アーカイブのときに、この design.md のルーリングを `docs/changes.md` に写す。
