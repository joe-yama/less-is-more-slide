# Design

## Context

動機は proposal.md の「Why」、振る舞いは 3 つの delta spec を参照。寸法と文字の大きさは、`manuscript.py`（判定）と `render.py`（描画）が同じ定数を使う（`tests/test_render.py` の `test_manuscript_and_render_share_size_definitions`）。構成図の配置も、判定と描画で同じ計算結果を使う（D1）。

## 合意事項（2026-10-14 設計の対話、PO が設計案を承認）

- 構成図は図のレイアウトの画像の行から `.flow` を参照する。書式は配置の行・箱の中の行・範囲の枠・矢印の 4 種（delta spec `flow-diagram`）。
- 箱の見た目、範囲の枠（1pt の破線、`BDBDBD`）、矢印（1.5pt、強調は ACCENT の 2pt）、× 印（32pt）、ラベル（12pt）、注記（16pt、3 行まで）は、PO が別の資料で使った値をそのまま使う。
- 図の強調の数え方は delta spec「構成図の強調」のとおり。
- 表・一言・中扉は、別の変更 `extend-table-statement-section` で行う。この変更を先に出す。
- 見送るものは proposal.md の「対象外」のとおり。

## Decisions

### D1 モジュールとデータ

- `slidekit/inline.py`（新規）: `Run`、`Text`、`runs(s) -> Text`、`is_emoji(ch)`、`inline_problems(s) -> list[str]`（インラインコード、リンク、`__`、`~~`、`*強調*`、閉じていない `**`）を `manuscript.py` から移す。`manuscript.py` は `Run` と `Text` を読み込み直して公開し、`render.py` の読み込みと理由の文言を変えない。
- `slidekit/flow.py`（新規）: `parse_flow(text: str) -> FlowSpec`。違反は `FlowError(problems: list[FlowProblem])`。`FlowProblem(line: int | None, message: str)` の `line` は構成図ファイルの行番号で、行に結びつかない違反は `None`。
  - `FlowSpec`: `columns: int`、`boxes: list[BoxSpec]`（配置の行の順に左上から）、`groups: list[GroupSpec]`、`arrows: list[ArrowSpec]`、`emphasis_lines: list[int]`（D8）。
  - `BoxSpec(name, col, row_top, row_bottom, lines: list[Text], line_no)`、`GroupSpec(label, members: list[str], line_no)`、`ArrowSpec(src, dst, emphasis, dashed, route: "straight" | "over" | "under", label: list[str] | None, cross: bool, line_no)`。
- `slidekit/layout.py`（新規）: `layout_flow(spec, max_w: float, max_h: float) -> Diagram`。違反は `FlowError`。`Diagram` は図の左上を原点とするインチの座標を持つ: `width`、`height`、`boxes: list[PlacedBox(x, y, w, h, name, lines)]`、`frames: list[PlacedFrame(x, y, w, h, label, label_x, label_y)]`、`arrows: list[PlacedArrow(points: list[tuple[float, float]], emphasis, dashed)]`、`labels: list[PlacedLabel(x, y, w, h, lines: list[str], emphasis)]`、`crosses: list[PlacedCross(x, y, w, h)]`。
- `manuscript.py`: 新しいスライド `DiagramFigure(heading, alt, ref, diagram: Diagram, note: Text | None, heading_gloss)` と、新しい塊 `DiagramBlock(alt, ref, diagram: Diagram)`。今の `Figure`・`ImageBlock` は変えない（互換のため）。参照が `.flow` で終わるとき、この 2 つを作る。
- `render.py` は `Diagram` を描くだけで、配置を計算し直さない。

### D2 解析の細部

- 行の種類は、前後の空白を除いた行の書き出しで決める（delta spec「構成図ファイルの行」）。判定の順は `|`、`- `、`[`、` -> ` を含む、の順。
- 配置の行のセルの分け方は、表の `_cells` と同じ。配置の行の間に別の種類の行があれば、後の配置の行で「配置の行は続けて書いてください」と拒否する。配置の行がなければ、行番号なしで拒否する。
- 矢印の行は ` -> ` で始点と残りに分ける。残りの末尾の `: ` より後をラベル、その前の末尾の ` (…)` を属性とする。属性の区切りは `,`（前後の空白は無視）。
- 名前・ラベル・枠のラベル・箱の中の行には、`inline_problems` と絵文字の判定を当てる。ラベルの `<br>` は改行で、それ以外の `<` で始まるタグは HTML として拒否する。
- `× ` で始まるラベルは `cross=True` とし、`× ` を除いた文をラベルの行とする。

### D3 寸法と文字の大きさ

文字の大きさ（pt）は `fit.py` に足す: `PT_BOX_NAME = 16`、`PT_BOX_LINE = 12`、`PT_FLOW_LABEL = 12`（矢印のラベル、枠のラベル、× の文）、`PT_CROSS = 32`、`PT_FLOW_NOTE = 16`。寸法（インチ）は `layout.py` に置く。

| 定数 | 値 | 定数 | 値 |
|---|---|---|---|
| `BOX_PAD_X`（左右それぞれ） | 0.12 | `BOX_PAD_Y`（上下それぞれ） | 0.08 |
| `BOX_MIN_W` / `BOX_MAX_W` | 1.2 / 3.0 | `BOX_MIN_H` | 0.6 |
| `COL_GAP` | 0.6 | `ROW_GAP` | 0.35 |
| `FRAME_PAD` | 0.15 | `FRAME_LABEL_H` | 0.3 |
| `LABEL_MARGIN` | 0.1 | `LANE_GAP` | 0.3 |
| `CROSS_SIZE`（× 印の正方形） | 0.45 | `NOTE_GAP` | 0.3 |

× 印の置き場所と重なりの判定には、一辺 `CROSS_SIZE` の正方形を使う。32pt の × の文字の枠は、この正方形に上下の中央をそろえて描き、行の高さがはみ出してもよい。線の太さ（pt）は `render.py` に置く: 箱 1.25、枠 1、矢印 1.5、強調の矢印 2。文字の幅と高さは `fit.text_width_em` と `fit.text_height_in` で見積もる（原稿と同じ見積もり）。

### D4 配置の計算

1. 箱の中身の幅 = 名前（16pt）と各行（12pt）の幅の最大 + 2×`BOX_PAD_X`。これが `BOX_MAX_W` を超える箱は拒否する（行番号は、超えた中の行。名前が超えたときは配置の行）。列の幅は、その列の箱の中身の幅の最大で、`BOX_MIN_W` 以上とする。箱のない列の幅は 0。
2. 枠の入れ子の深さを、辺ごとに数える。枠 F の左辺の深さは、F に含まれる枠（F 自身を含む）のうち、左端の列が F と同じものの入れ子の段の数。右・上・下も同じ。列 c の左の余白 L(c) は、左端が c の枠の左辺の深さの最大 ×`FRAME_PAD`。右の余白 R(c)、下の余白 B(r) も同じで、上の余白 T(r) は深さ ×（`FRAME_PAD` + `FRAME_LABEL_H`）。
3. 列 c と c+1 の間 = R(c) + max(`COL_GAP`, その間に置くラベルの要る幅) + L(c+1)。行も同じく、B(r) + max(`ROW_GAP`, ラベルの要る高さ) + T(r+1)。最初の列の左は L(0)、最後の列の右は R(最後)、上下も同じ。ラベルの要る広さは D6。
4. 箱の中身の高さ = 16pt の 1 行 + 12pt の行数分 + 2×`BOX_PAD_Y`。行の高さは、1 行だけの箱の中身の高さの最大で、`BOX_MIN_H` 以上とする。箱のない行の高さは 0。行をまたぐ箱の中身が、またいだ行とその間の高さの合計より高いときは、またいだ行を同じだけ高くする。
5. 箱の位置は、列と行の位置から決める。枠の長方形は、メンバーのセルを囲む長方形を、辺ごとの深さ ×（2 の余白）だけ外へ広げたもの。枠のラベルは、枠の左上から右へ 0.1、下へ 0.05 の位置に置く。
6. 回り込みの通り道と、ラベル・× を置き（D5・D6）、すべての要素を囲む長方形の左上を原点に移す。その幅と高さを、`max_w` と `max_h` と比べる（delta spec「構成図の大きさの上限」）。

範囲の枠の判定（`layout.py`）: 枠の長方形に、メンバーでない箱のセルが入るとき、または 2 つの枠のメンバーが一部だけ重なるときは、その枠の行で拒否する。枠のラベルの幅が、枠の幅から 0.2 を引いた幅を超えるときも拒否する。

### D5 矢印の経路

- 直線の端点（delta spec「矢印の経路」）: 列が違えば、始点の箱の終点側の辺の中央から、終点の箱の始点側の辺の中央へ結ぶ。列が同じなら、上下の辺の中央どうしを結ぶ。行をまたぐ箱は、箱全体の辺の中央を使う。
- 回り込み: `上回り` の矢印には、書いた順に 1 番目、2 番目、…の通り道を与える。k 番目の通り道は、すべての箱と枠の上端から、`LANE_GAP` と、1〜k-1 番目の通り道の外側に置くラベルと × の高さを足し、k 番目の通り道に × があれば `CROSS_SIZE` の半分も足した分だけ上にある。経路は、始点の上辺の中央、その真上の通り道、終点の上辺の中央の真上、終点の上辺の中央の 4 点を結ぶ。`下回り` は上下を逆にする。
- 拒否（矢印の行で）: 線分が始点と終点以外の箱の内側を通るとき、線分が枠のラベルを通るとき、同じ列の箱どうしの回り込み、同じ箱の同じ辺から出入りする 2 本目の回り込み。辺や角に触れるだけのものは通るとみなさない（1e-6 インチの許容）。

### D6 ラベルと × の置き方

- ラベルの大きさ: 幅は各行の 12pt での幅の最大、高さは行数 ×12pt の 1 行の高さ。× 印は一辺 `CROSS_SIZE` の正方形で、文は × 印の右に 0.05 離して置く。
- 置く点（基準点）: 直線では、線分のうち、列の間（垂直な線では行の間）から枠の余白を除いた範囲にある部分の中点。回り込みでは、横向きの線分の中点。
- 候補の順（最初に重ならないものを使う）:
  - 水平な直線: 基準点の下に、左右の中央をそろえ、`LABEL_MARGIN` だけ離す。
  - 垂直な直線: 基準点の右に、上下の中央をそろえて離す。
  - 斜めの直線: まず線の下側。右下がりなら、ラベルの右上の角を基準点の `LABEL_MARGIN` 下に置く。右上がりなら左上の角を置く。次に上側（右下がりなら左下の角、右上がりなら右下の角を、基準点の `LABEL_MARGIN` 上に置く）。
  - 回り込み: 横向きの線分の外側（`上回り` は上、`下回り` は下）に、左右の中央をそろえて離す。
- × 印: 基準点を中心に置き、文は × 印の右の外側（直線と `下回り` は下側、`上回り` は上側）に置く。候補は上の順と同じ。
- 間隔を広げる量（D4 の 3）: 隣り合う列を結ぶ水平な直線のラベルは、ラベルの幅 + 2×`LABEL_MARGIN`。隣り合う列を結ぶ斜めの直線のラベルは、2×（ラベルの幅 + `LABEL_MARGIN`）。ラベルは基準点の片側に置くので、2 倍の幅を取る。同じ列の隣り合う行を結ぶ垂直な直線のラベルは、行の間を、ラベルの高さ + 2×`LABEL_MARGIN` まで広げる。隣り合わない列や行を結ぶ直線のラベルは、間隔を広げず、重なりの判定だけをする。

### D7 重なりの判定

ラベル・× 印・× の文を、書いた順に 1 つずつ置く。候補の長方形が次のどれかに重なれば、次の候補に進む: 箱、枠の 4 辺と枠のラベル、すべての矢印の線分（そのラベルの矢印を含む。ただし × 印は経路の上に置くものなので、自分の矢印との重なりは見ない）、それまでに置いたラベル・× 印・文。すべての候補が重なれば、その矢印の行で「ラベル（または × の文）を置ける場所がありません」と拒否する。

### D8 強調の数え方

- `flow.py` は、強調のある構成図ファイルの行を `emphasis_lines` に持つ。`強調` の矢印の組（最初の `強調` の矢印の行）と、`**` を持つ箱の中の行が入る。
- `強調` の矢印に共通の箱がないときは、共通の箱を持たなくなった最初の矢印の行で拒否する。構成図ファイルの中で強調が 2 か所になったときは、2 か所目の行で拒否する。
- `manuscript.py` は、原稿の行の順に強調を数える。構成図の強調は、その画像の行で数える。2 か所目になった原稿の行で「強調は 1 枚のスライドに 1 か所までです」と拒否する。たとえば、構成図に 1 か所あり注記にも 1 か所あれば、注記の行で拒否する。

### D9 描画

- 構成図は `add_group_shape` の 1 つのグループにまとめる。名前は `構成図`、代替テキスト（`p:cNvPr` の `descr`）は `説明` とする。グループの位置は、図のレイアウトでは（`MARGIN_X`、`BODY_TOP`）、左右 2 列では塊の左上（今の画像の塊と同じ x と `BODY_TOP`）。
- 箱と枠は、長方形の図形（`MSO_SHAPE.RECTANGLE`）にし、塗りをなくして線を明示する。箱の文字は図形の文字の枠に入れる: 余白は `BOX_PAD_X` と `BOX_PAD_Y`、上下の中央にそろえ、左寄せにする。名前の段落の次に、中の行の段落を並べる。枠のラベルは別の文字の枠にする。
- 直線はコネクタ（`add_connector` の直線）、折れ線は `build_freeform` の開いた経路で描く。どちらも線の終わりに `a:tailEnd type="triangle"` を付け、`破線` と枠の線には `a:prstDash val="dash"` を付ける。
- python-pptx が図形とコネクタに付ける `p:style`（テーマの書式の参照）は取り除く。見た目は明示した属性だけで決める（delta spec「装飾を持たない」）。
- ラベル・× 印・× の文は、文字の枠（余白 0、折り返しなし、左寄せ）で描く。文字の色と書体の付け方は、今の `_style_run` を使う。
- 注記は、図の下端から `NOTE_GAP` 下に、幅 `BODY_W` の文字の枠で描く。

### D10 判定と描画の順序

`manuscript.py` は、`.flow` の参照を読んだときに `parse_flow` と `layout_flow` を呼ぶ。`max_h` は、図のレイアウトでは、`BODY_BOX_H` から注記の高さと `NOTE_GAP` を引いた値（注記がなければ `BODY_BOX_H`）、左右 2 列では `BODY_BOX_H`。`max_w` は `BODY_W` か `COLUMN_W`。構成図ファイルの違反は、画像の行の違反として報告する（delta spec「構成図の違反の報告」）。今の格子ファイルの `_grid_message` と同じ組み立て方にする。ファイルを読めないときの理由は「構成図ファイル <参照> を読めません」とする。

### D11 互換

`examples/sample.md` の出力は変えない。`tests/test_compat.py` の基準を作り直してはならない。`inline.py` への移動の後も、理由の文言と `Run` の生成は同じにする。

### D12 見本と文書

- `examples/design-review.md` と `examples/design-review/*.flow`（ファイル名は ASCII）: 表紙と、設計の対話で示した 7 つの図（設計の相談の資料の形）。後の変更 `extend-table-statement-section` が、表・一言・中扉のスライドをこの原稿に足す。図 5 は左右 2 列で、ほかは図のレイアウト。注記のあるものを 2 枚以上含める。中身は一般の例だけにし、社内の資料の内容を入れない。
- `references/format.md` に「構成図」の節を足す。`flow` という言語名で囲んだ構成図ファイルの例と、それを参照する原稿の例を載せる。原稿の例が参照する構成図ファイルは `構成.flow` だけとし、テストは文書の最初の `flow` の例をその名前で置いてから生成する。
- `SKILL.md`: 書式の要約に構成図の 1 段落と、`flow` の短い例を 1 つ足す。`writing.md`: 規則に「構成図は構成や流れを説明するときだけ使う」「構成図の強調は、言いたい点の 1 か所だけ」を足す。AI っぽさの 10 番に、飾りの構成図を含める。
- 版は 0.3.0（`plugin.json` と `marketplace.json`）。

### 2026-10-14 比べ図は左右 2 列で描く
- Ruling: 2 つの構成を並べる図は、左右 2 列のレイアウトに `.flow` を 1 つずつ置いて描く。左右の見出し（「今の形」「案の形」）は、それぞれの構成図の範囲の枠のラベルで書く。
- Reason: 1 つのファイルに 2 つの構成を書くと、同じ名前の箱が 2 つ要り、名前で矢印を結ぶ書式が成り立たない。左右 2 列は、今の書式で比べるための形である。
- Cost if wrong: 枠で囲むのが不自然な比べ図が描けない。見本を見た PO の判断で、塊の上に 1 行の見出しを置く書式を、別の変更で足す。

### 2026-10-14 箱の中の文字は左寄せにする
- Ruling: 箱の名前と中の行は左寄せにし、上下は中央にそろえる。
- Reason: spec「装飾を持たない」は、ページ番号を除くすべての段落を左寄せにすると定めている。一覧の箱（図 7）も、左寄せのほうが読みやすい。
- Cost if wrong: 中央寄せに慣れた読み手に、箱が片寄って見える。PO が見本で判断する。

### 2026-10-14 構成図の注記に添え訳をつけない
- Ruling: 構成図の注記の添え訳は拒否する。
- Reason: 添え訳の大きさの一覧（spec「添え訳の文字」）に 16pt の対象を足す要件の変更が、並行する `extend-table-statement-section` の変更とぶつかる。今のところ使う人もいない。
- Cost if wrong: 英語の資料で構成図に訳を添えられない。求められたら、別の変更で足す。
