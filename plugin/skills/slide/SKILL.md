# スライドを作る

原稿（Markdown の部分集合）を書き、生成器に渡して PPTX にする。配色・書体・大きさ・位置は生成器が決めるので、原稿の書き手が決めるのは内容だけ。規則に反する原稿は生成器が拒否する。

以下の `<Skill のフォルダ>` は、この `SKILL.md` があるフォルダのこと。コマンドは uv で動く。ほかに入れるものはない。

## 手順

1. 主題・聞き手・枚数・材料を確かめる。足りなければ利用者に聞く。
2. `references/writing.md` の書き方の規則と、避ける癖の一覧（12 項目）を読む。
3. 作成役 Agent `writer` に原稿と PPTX を作らせる。依頼の文に、この Skill のフォルダの絶対パスを書いて渡す（Agent はプラグインの場所を知らないため）。使えない環境では、この手順を自分で行う。
4. 点検役 Agent `critic` に原稿を点検させる。依頼の文に、この Skill のフォルダの絶対パスを書いて渡す。指摘があれば作成役に戻して直させる。点検は最大 2 回まで。
5. 原稿と PPTX のパスを利用者に伝える。

## 生成する

```sh
uv run <Skill のフォルダ>/scripts/build.py 原稿.md -o 出力.pptx
```

違反があると終了コード 1 になり、標準エラーに `<原稿のパス>:<行番号>: <理由>` が 1 件 1 行で出る。出力先のファイルは変わらない。理由に沿って原稿を直し、通るまで繰り返す。PPTX を直接編集してはいけない。

## 原稿の書式（最短）

`---` だけの行でスライドを区切る。最初のスライドは表紙。6 種のレイアウトを次の 1 つの原稿で示す。詳しい書式と制限値は `references/format.md`。

```markdown
# 夜間バッチの移行報告

情報システム部 山田

---

結論から言うと、実行時間は 4 時間から 50 分に縮んだ。

---

## 移行でやったこと

- 旧サーバー 3 台を新しい 1 台に集約した
- 失敗時の再実行を **自動** にした

---

## 夜間の処理

![歯車](icon:gear)
毎晩 1 時に起動する。

---

## 実行時間の変化

| 処理 | 移行前 | 移行後 |
|---|---|---|
| 売上集計 | 2 時間 10 分 | 25 分 |
| 在庫集計 | 1 時間 30 分 | 15 分 |

---

## 残った作業

- 月次集計の移行は 11 月
|||
![箱](icon:box)
```

上から順に、表紙、一言、箇条書き、図、表、左右 2 列。

## ドット絵

図には、文字の格子から作るドット絵か、同梱のアイコン（`icon:<名前>`）を使う。写真や外部の画像は使えない。原稿の `![説明](参照)` に書くだけで、PNG への変換は生成器が行う。

格子ファイルは `.` が透明、`#` がほぼ黒、`+` が灰色、`*` が強調色の 4 文字だけで書く（大きさの上限はない）。PNG を単独で作る、同梱アイコンの名前を調べる、には次のコマンドを使う。

```sh
uv run <Skill のフォルダ>/scripts/pixel.py --list
uv run <Skill のフォルダ>/scripts/pixel.py icon:gear -o gear.png
uv run <Skill のフォルダ>/scripts/pixel.py 格子.txt -o 出力.png --scale 16
```

同梱アイコン（14 個）: `person` `people` `arrow-right` `arrow-down` `box` `document` `gear` `clock` `check` `cross` `cloud` `computer` `magnifier` `chat`。
